# Remix Table audio implementation

NIVIROTest starts automatically with four stereo sources (Drums=drums, Bass=bass, Melody=other, Vocals=vocals). Other library entries remain silent placeholders. No packages or XR configuration changed.

RemixAudioManager schedules all sources at one DSP timestamp, 200 ms ahead. Equal-length clips loop inside Unity audio. Pause captures DSP position and stops all sources; resume seeks all four to the same sample and schedules a common restart. The shared clock remains fixed during the scheduling lead-in. Selection acquires a shared editing-pause owner: all stems and the DSP timeline pause, and all ribbons read that fixed timeline while mesh sculpting continues. Releasing the final owner schedules synchronized playback from the stored position. Manual pause is independent and remains in effect after editing. Use audioManager.Pause()/Resume() for manual controls (including while editing); legacy clock.playing changes are observed when they differ from transport state. Application suspension is a separate pause reason and respects manual/editing pauses. Disabled or destroyed owners are cleaned up; gesture cancellation and tracking loss release selection. Two-hand editing retains the session when the primary hand releases while the participating second hand holds.

Whole-stem and region-specific gain are audible through the existing AudioSources. Effective gain is whole-stem gain multiplied by the evaluated region factor, clamped to 0..2.5. The shared evaluator drives ribbon waveform amplitude and persistent tint as well as audio. Stored pitch edits and the optional twist effect remain visual only; no pitch shifting or effect DSP is claimed. Audio analysis uses reused 128-sample buffers and RMS, without FFT or per-frame buffer allocations.

Source WAVs are unchanged: stereo float32, 44,100 Hz, 10,143,744 frames each (about 230 seconds), 324,600,160 total file bytes (~309.6 MiB). Measured absolute peaks: bass .857569, drums 1.477390, other 1.302390, vocals .914710. Master per-source headroom .06 limits the sum of peak bounds at maximum 2.5 gain to .683 (before codec overshoot). Streaming Vorbis quality .85 for default and Android avoids full PCM decompression residency. Unity transcoding may clip float samples above unity before source gain; headroom prevents mix overload but cannot recover any clipping introduced by the importer. Original files remain available for a future float-preserving decode path. Actual decoder memory, compression size, seek accuracy, streaming CPU, audible seam quality and any importer clipping require profiling/listening on device.

Editor tooling: RemixTable.Editor.RemixAudioSetup.Configure updates only the existing Remix scene and stem import settings; Validate checks the inherited rig plus exactly one active listener and exactly four assigned, non-autoplay sources. After regenerating the scene with RemixSceneBuilder, rerun Configure.

The user reports that prior playback, XR interactions, and global pause/resume passed Quest 3 hardware testing. This region-gain change has not been tested on Quest 3 by this implementation. New audible gain transitions, Android streaming timing and performance still need device validation. Desktop tests cannot establish these hardware results.

## Audible region gain

The existing AutomationStore and AutomationEdit objects are used directly. Edits remain in memory by song ID and StemId for the current session; no disk/cloud storage was added. Melody maps to other.wav. There is no new audio routing or DSP package. AudioSource references, scene geometry, materials, XR rig and passthrough are unchanged.

Gesture update: one-hand vertical drag now writes audible gain, not pitch. Two-hand pinching always selects/adjusts boundaries continuously from both local X coordinates, independent of hand Y arrangement. Release either hand to continue gain editing with the remaining hand. Neutral gain is 1; defaults are 0..2.5, 12 cm per gain unit, sensitivity 1, and an 8 mm initiation threshold. Holding an endpoint still selects whole-stem gain. Stored pitch data and optional visual wrist twist are preserved. Invalid inputs remain sanitized. See README.md for the current controls.

Precedence: the latest updated whole-stem gain is the base. Regions are layered oldest to newest; each replaces the underlying region factor in its interior and blends with it at the boundaries. Regions do not multiply one another. The resulting factor multiplies the base. Upsert moves an updated ID to the end without duplicating it. Re-editing a matching interval (endpoints within 25 ms) reuses its ID and updates its endpoints; a different interval adds a new layer. Song and stem IDs isolate all edits. Previously authored gain curves still evaluate; a new gain drag of an existing region replaces its curve with the new scalar plateau and boundary fades. Pitch/effect curves and data are preserved.

Permanent region endpoints come from ribbon-local X mapped against the frozen song timeline, not world positions. Horizontal endpoint order is resolved before wrapping. start > end denotes a region across the loop seam. Wrapped midpoint, highlighting, and curve offsets use the forward interval. Wrapped regions fade at their true endpoints, with no extra fade at time zero. Regions starting at zero or ending at duration fade at those endpoints. Equal endpoints are a zero-length region and are ignored; use whole-stem mode for a complete song.

Boundary envelope: SmoothStep from neutral/underlying factor to region gain over gainBoundaryFade (default 60 ms), and back at the other end. Each fade is shortened to half the region for very short intervals. AudioSource.volume additionally follows the effective target with an exponential time constant gainSmoothingSeconds (25 ms). During editing the DSP timestamp stays fixed; volume can settle to the edited target while silent, including during the 200 ms common resume lead-in. Automation never advances from frame time. Only the smoothing coefficient uses unscaled delta time. No per-frame automation buffers or curves are allocated.

The visual waveform and persistent gain tint use the same effective evaluator at each displayed song timestamp, including after release and looping. Audio-reactive displacement is scaled by that local gain. The existing ribbon shape is still procedural, not a decoded waveform display. Visual amplitude shows the automation target; audible volume follows it with the smoothing lag.

Headroom remains 0.06 per source and is now capped there at runtime even if its Inspector field is raised. With measured source peaks and final 2.5 maximum gain, the conservative sum bound is ~0.683 before codec overshoot. WAVs and import settings are unchanged in this update. This cannot undo clipping introduced during Unity import of float samples above unity.

Precision limitation: this MVP evaluates DSP-relative position and sets AudioSource.volume once per rendered frame. It is not a sample-accurate audio-thread envelope. Boundary timing can lag by a frame plus the smoothing/audio-buffer latency; very short regions can be missed at low frame rates. SmoothStep fades and exponential smoothing reduce abrupt transitions, but click-free output under stalls and Android decoder behavior require listening on hardware. A future sample-accurate solution would need an audio-thread-safe automation snapshot/routing layer. No such DSP precision is claimed here.

## Hands-first interaction correction

Source-level causes of the reported failure: the prior handler wrote horizontal endpoints only on second-hand pinch entry, never as either hand moved. A one-time comparison of hand Y/X separation locked the session into region or stretch mode, making it easy to enter the unintended mode. One-hand vertical motion still wrote visual Pitch instead of audible Gain, so the reliable gesture bypassed gain entirely. Additional rejection paths required a wrist pose for any pinch and rejected the second hand outside a fixed 12 cm local-Z slab. Both XRHandSubsystem hands were already queried; this was not an absent second-hand API. Actual device-specific tracking dropouts were not measured here.

The existing RibbonInteractionManager now has explicit Idle / OneHandGain / TwoHandRegion transitions. Its runtime XR adapter reads leftHand and rightHand independently, preserving each hand's own pinch hysteresis. Only index/thumb pose validity is required; optional wrist validity gates the old twist preview. Both pinches always enter boundary mode and continuously update each boundary from ribbon-local X. Vertical separation and depth no longer classify or reject the joining hand. The selected ribbon keeps its single editing-pause owner through hand joins, handoff and one-hand continuation. If either participating hand releases or loses tracking, the remaining hand inherits the session with a fresh local-Y baseline. Both hands ending, ribbon deactivation, cancellation or handler disable release ownership without deleting edits. Manual pause still takes precedence.

One-hand local Y now maps to existing Gain automation: initial region factor + local Y displacement / gainDragDistance * gainGestureSensitivity, clamped by existing min/max and hard 0..2.5 safety. Defaults: 12 cm per gain unit, sensitivity 1, 8 mm initiation deadzone. Gain continues updating back to the starting point after activation, so reversing a drag restores its baseline. Two-hand movement creates no gain or pitch edits; if a gain edit already exists in the current session it is resized by ID without changing its value. The existing timestamp mapping, shared evaluator, fades, source volume smoothing and headroom are reused unchanged. Stored pitch records are preserved, but no new pitch is authored by the vertical gesture. The Remix scene and scene builder instruction labels now say GAIN / REGION.

Automated verification (Unity 6000.3.23f1): compilation passed; saved scene and audio validation passed. Edit Mode 27/27 passed (Logs/RemixHandsEdit.xml); Play Mode 6/6 passed (Logs/RemixHandsPlay.xml). Added HandGestureTests exercises the same ProcessHands path used by the XR adapter: independent pinch hysteresis, either hand selecting, local-coordinate gain, continuously moving wrapped boundaries, no boundary-mode gain writes, either-hand handoff, edit persistence/resize, endpoint whole-stem mode and cancellation. GestureGainTests drives hand samples through region selection, downward gain editing, persistent evaluation and actual Bass AudioSource.volume; it checks unaffected stems, frozen four-ribbon timeline, resume/volume restoration, stem sample alignment, manual pause and disabled-handler cleanup.
